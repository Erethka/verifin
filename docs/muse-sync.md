# Muse 账单同步

在一个 Muse 专用对话中记录消费，每日任务将逐笔明细提交到自建 HTTPS 服务。Android 端的 VeriFin 下载明细并保存到指定账本。

## 运行方式

- 设置入口为「我的 → 设置 → Muse 账单同步」，默认关闭。
- 新账单保存到所选账本，付款方式写入备注，账户设为「无账户」。分类名称与现有同类型分类完全相同时复用，否则使用「未分类」。
- 相同服务器数据库和账单编号对应同一条本地记录。修正金额、日期、分类和备注时更新原记录，保留原账本、账户和标签。
- 手机启动和回到前台时同步。Android `JobScheduler` 每约 15 分钟安排后台尝试，系统省电策略可能延后执行。后台任务与界面共用 Flutter 引擎和控制器。
- 单次最多读取 20 页，每页最多 100 条，运行到 55 秒后停止发起下一页。剩余内容留到下一次同步。
- 账单成功写入 SQLite 后才保存读取进度。网络和数据库失败后可以用同一编号重试。
- 设置地址、账本和进度保存在设备本地，独立于账单 JSON 备份。读取密钥与服务地址一起通过 Android Keystore 的 AES-GCM 加密存储，仅返回给匹配地址，并排除在 Android 云备份与设备迁移之外。更换手机后重新配置读取密钥。
- 初始化会关闭同步并保留进度。重新开启后只接收后续变更。
- 服务器恢复备份后，可点「重新读取服务器账单」从头读取，匹配编号更新已有记录。已在手机手动删除的远程账单也会再次导入。恢复时须保留数据库中的 `meta.stream`，它是账单来源的一部分。

## HTTPS 服务

实现位于 `services/muse_sync/`，使用 Python 3 标准库与 SQLite。Nginx 提供 HTTPS，并将请求转发到 `127.0.0.1:18791`。

| 入口 | 授权 | 操作 |
| --- | --- | --- |
| `POST /v1/entries` | 写入密钥 | 批量新增、修正来自 Muse 的账单 |
| `GET /v1/entries?cursor=0` | 读取密钥 | 分页读取明细与游标 |
| `POST /mcp` | 写入密钥 | 无状态 MCP Streamable HTTP，提供 `submit_bills` 工具 |
| `GET /openapi.json` | 公开 | 获取写入接口的 OpenAPI 描述 |

MCP 使用 JSON 响应，支持 `initialize`、`ping`、`tools/list`、`tools/call` 和初始化通知。具体接入方式需要按 Muse 账号提供的连接器界面验证，可使用 MCP 地址或 OpenAPI 描述。定时任务由用户在 Muse 中配置。

每次批量提交 1–100 条明细，请求体上限为 128 KiB。只接受人民币支出和收入，金额为最多两位小数的正数字符串。每条记录的 `id` 固定且唯一，可使用字母、数字、下划线和短横线，最长 80 字符。

```json
{
  "entries": [
    {
      "id": "muse-20261116-0001",
      "occurred_at": "2026-11-16T12:30:00+08:00",
      "type": "expense",
      "amount": "12.50",
      "currency": "CNY",
      "category": "餐饮",
      "merchant": "面馆",
      "payment_method": "支付宝",
      "note": "午饭"
    }
  ]
}
```

这是一条示例记录。成功响应包含 `accepted` 和 `changed`，代表接收条数和实际变更条数。整个批次先校验后提交，同编号同内容重发时 `changed` 为 0。

## 部署与权限

`install.sh` 针对已检查的 Debian 13 主机，要求现有 nftables 使用 `inet host_filter`，并具有开放 22、443、8443 的规则。执行前复核实际布局，备份需要修改的配置。

1. 准备自己控制的域名或子域名，将 A 记录指向 VPS。
2. 将 `services/muse_sync/` 上传到普通管理员的私有暂存目录。
3. 在该目录运行测试。
4. 输入管理员密码执行安装脚本。
5. 验证证书、接口授权、服务隔离、续期和备份。
6. 配置手机读取密钥，再配置 Muse 写入密钥。

```bash
python3 -m unittest -v
sudo bash install.sh bills.example.com
```

脚本使用独立 HTTPS 9443 端口。80 端口用于 Let's Encrypt HTTP-01 证书申请与续期。域名需能从公网直接解析到该服务器；DNS 服务的 CDN 代理模式可能影响 9443 和证书验证。

- `verifin-sync` 系统用户使用禁止登录的 shell，程序文件由 root 持有。
- 服务只能写入自己的 StateDirectory，使用 systemd 文件系统、进程与设备访问限制。
- systemd IP 规则限制服务与回环地址通信，系统调用规则拒绝主动 `connect` 并返回 `EPERM`，服务通过已接受的连接回复请求。上线时须确认宿主支持并实际生效。
- CPU 配额为单核 25%，内存上限为 128 MiB，进程数上限为 8。
- 写入和读取密钥独立生成，放在 root 的 `/etc/verifin-sync/` 中，通过 `LoadCredential` 交给服务。
- 服务器最多保存 50000 条记录，SQLite 主数据库上限约 128 MiB。容量用尽时提交失败并保留已有记录。
- Nginx 限制每来源每秒 2 个请求，允许短时突发 30 个，全服务并发连接最多 4 个，并限制请求体和超时。
- Nginx 检查 Host 和 Origin。接口日志省略账单、密钥和请求路径，程序异常使用固定诊断文案。
- 证书由 `certbot.timer` 自动续期，续期后检查并重载 Nginx。
- 每天由独立的 root 备份任务创建 SQLite 快照，保留最近 7 天，放在 `/var/lib/verifin-sync-backups/`。快照包含服务数据库的来源标识。该备份仍位于同一台 VPS，整机丢失时也会丢失。

成功安装后，普通管理员的 `~/.verifin-setup/` 中会生成 `server-url`、`write-token`、`read-token`，目录权限 0700，文件权限 0600。通过可信 SSH 连接配置客户端，配置完成后移除交接副本。把密钥填到连接器的认证设置中，并在手机同步页输入读取密钥。

管理员凭据用于安装和维护。接口只提供账单提交与读取操作。撤销或轮换时替换对应的 root 密钥文件并重启 `verifin-sync.service`，随后更新对应客户端。

## Muse 专用窗口提示词

把连接器配置好后，在专用窗口使用这段提示词，并在 Muse 中设置每天北京时间 00:10 执行每日任务。

```text
这个窗口用于记录我的逐笔收支，并通过 VeriFin 连接器同步。

每次我说一笔消费或收入，请整理金额、发生时间、用途、分类和付款方式。
金额使用人民币字符串，保留两位小数。支出 type=expense，收入 type=income。
时间使用北京时间并附 +08:00。日期缺失时按消息当天记录，时间不清楚时向我确认。
每笔分配永久唯一编号，例如 muse-20261116-0001。
纠正同一笔内容、重试提交和每日总结时，沿用该笔编号。
逐笔展示你记下的内容，让我可以纠正。

每天北京时间 00:10 总结前一天的收支，并提交全部待同步明细和待同步修正。
通过 submit_bills 工具或已配置的 submitBills 接口提交。
每批最多 100 笔，并控制请求大小。以连接器的实际返回为依据确认提交成功。
失败时保留待同步状态，下次用原编号重试，并告诉我失败情况。
每天汇总总额只用于展示。逐笔明细才进入 entries。
```

## 验证

本地 Flutter 检查使用 `flutter analyze` 和 `flutter test`。服务端检查使用 `python3 -m unittest discover -s services/muse_sync -p 'test_*.py' -v`，Linux 环境同时验证系统调用限制下的 HTTP 启动与连接拒绝。

公网部署后，用标记清楚的示例记录检查新增、重复提交、修正和手机入账，确认写入密钥读取被拒绝、读取密钥写入被拒绝、错误密钥被拒绝。确认 18791 和凭据目录仅在服务器内部可访问，复核服务资源限制、备份以及证书续期。

## 已知限制

Muse 的对话记录、任务执行和连接器调用取决于 Muse 提供的功能及账号授权。上线验收需要真实连接器和 Android 手机参与。系统省电、强行停止应用或断网会延后同步，打开应用后可手动同步。

HTTPS 域名与 DNS 账号的控制权、服务器系统更新和密钥保管由部署者负责。独立服务账号可限制程序漏洞的影响，主机级漏洞和大规模网络攻击仍会影响同机服务。
